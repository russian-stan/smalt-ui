# example

A smoke-test consumer of the library on **Vite + Vue 3**: a minimal app that includes
`@smalt-ui/core` the way an external consumer would and checks that consumption and
**tree-shaking** work. A private app (not published).

> Part of the **Smalt UI** monorepo. Shared requirements and installation are described in the
> [root README](../../README.md).

## Purpose

- Check that the built `@smalt-ui/core` (ESM + styles) is consumed correctly by a third-party
  bundler.
- Make sure per-component imports pull in nothing extra (tree-shaking).
- Check **auto-import** in a real build: components are not imported in templates and the `SUI`
  plugin is not installed; `SUIResolver` from `@smalt-ui/core/resolver` provides them via
  `unplugin-vue-components` (configured in `vite.config.ts`). The resolver unit test only sees the
  "name → package" pair; here the whole chain is checked to actually work.
- Check the `@smalt-ui/core/icons` subpath + `registerIcons`.

The app is **not** a component showcase: that is what the [documentation](../docs/README.md) is
for; it is built against the built package (`pnpm test:dist`) and shows every component.

## Scripts

| Script                 | Description                                                           |
| ---------------------- | --------------------------------------------------------------------- |
| `pnpm dev`             | Vite dev server                                                       |
| `pnpm build`           | Production build                                                      |
| `pnpm build:treeshake` | Build with the `vite.treeshake.config.ts` config (tree-shaking check) |
| `pnpm preview`         | Preview the built app                                                 |

Run from the root: `pnpm --filter example <script>`.

> The app consumes `@smalt-ui/core` from the workspace, so build the core first
> (`pnpm --filter @smalt-ui/core build`) or build the whole workspace with `pnpm build`.
> The resolver needs this too: it is imported from the built `dist/resolver.js`.
>
> `src/components.d.ts` is generated by the auto-import plugin during dev/build and is not
> committed.
